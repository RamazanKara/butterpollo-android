# Build, quality and security bug hunt

Audit date: 2026-10-09. Starting revision: `10ba65e8` on the Android main worktree.

Read `PARITY-MATRIX.md`, `TROUBLESHOOTING.md`, and `git log -30`, including the recent release/R8, crash-reporting, accessibility, ADPF-default and overlay changes. No host files, commits, pushes, PRs, adb commands or emulator runs were used. No dependencies were added or upgraded.

## Fixed findings

Severity describes the client impact, not an assigned CVSS score. Native and Android lifecycle fixes below have build/static verification; they are not claimed as device-tested.

| # | Severity | Bug and root cause | Minimal fix | Regression/verification |
| --- | --- | --- | --- | --- |
| 1 | Medium | An exported frontend entry could exhaust memory before its 16,384-character limit was checked. `BufferedReader.readLine()` allocated an entire attacker-controlled line first. Its synthetic newline accounting also rejected an exactly-at-limit file without a final newline. | `FrontendEntry.parse()` reads at most `MAX_CHARS + 1` characters before parsing and measures the actual input. | Two new JVM tests: a reader that fails on over-read, and an exactly-at-limit entry. Both failed before the fix. |
| 2 | Low | A desktop UTF-8 BOM before the exported comment or a blank line made a valid `.art` file fail parsing. Comment/empty checks preceded BOM removal. | Remove the BOM before classifying the line. | New BOM/comment/blank-line JVM test failed before the fix. |
| 3 | Medium | `ShortcutTrampoline` unbound after polling without clearing `managerServiceBound`; the following `onStop()` unbound again and could throw `IllegalArgumentException`. | Clear the flag at that unbind site, matching the other lifecycle paths. | Reviewed all three unbind paths and main-thread ownership; Android lifecycle exercise remains pending. |
| 4 | Medium | On API 21–32, other apps could spoof `com.limelight.USB_PERMISSION`, consume a pending device ID and interfere with the legitimate permission callback. Only API 33+ registration was unexported. This did not bypass `UsbManager.hasPermission()`. | Use the existing AndroidX `ContextCompat.RECEIVER_NOT_EXPORTED` pattern on every API. | Compile and merged-manifest permission check; pre-33 USB permission delivery/spoof rejection needs a device. |
| 5 | Medium | HDR metadata arrays accumulated JNI local references on an attached native control thread. Returning from the C callback does not release those references. | Delete the local array reference after the Java callback. | All-ABI native compilation and reference-lifetime review; repeated HDR changes with CheckJNI pending. |
| 6 | Medium | Each growth of the native video buffer retained a local reference to the replacement array. Deleting its global reference on the next growth did not allow collection while the decoder thread remained attached. | Keep the temporary array handle and delete its local reference after creating the global reference. | All-ABI native compilation; increasing-frame-size memory stress pending. |
| 7 | Low | Text input treated JNI modified UTF-8 as wire UTF-8. Embedded U+0000 became the invalid UTF-8 sequence `C0 80`, and unpaired surrogates were not normalized. Supplementary-character behavior also depends on the runtime; modern ART already emits four-byte sequences, so this is not a claim that emoji failed on every Android version. Existing keyboard tests stopped at a Java string sink. | Encode with `StandardCharsets.UTF_8` before JNI, pass a byte array and its explicit length, and release it with `JNI_ABORT`. | Java/native signature and build checks; existing Unicode/input-role tests retained. No host-side Unicode round trip was run. |
| 8 | Medium | The root input helper's supposedly local `ServerSocket` bound to all interfaces. A LAN peer racing the helper could supply input records or break capture. | Bind explicitly to IPv4 loopback, matching the C helper's `127.0.0.1` destination. | Socket constructor/address reviewed; root release build. A rooted device is needed for the connection-race exercise. This is not authentication against other local apps. |
| 9 | Medium | The root `EvdevReader` trusted arbitrary packet lengths above 15, allowing huge allocations or misparsed intermediate sizes. Native input events have only 16- and 24-byte layouts. | Accept exactly those two lengths before allocating or reading a payload. | New root JVM rejection test failed on a 17-byte record before the fix. A second test protects both legitimate layouts and signed event values. |
| 10 | Medium | The native root helper's `grabbing` flag was written by its command thread and read by polling threads without synchronization: a C data race. | Make the shared flag `atomic_int`. | Root native compilation for every ABI; rapid grab/ungrab hardware stress pending. |
| 11 | Low | Root device polling threads were joinable but never joined or detached. Hotplug cycles leaked terminated thread resources. | Detach each successfully created polling thread while the device-list mutex still protects its context. | Root native compilation and create/cleanup ordering review; hotplug stress pending. |
| 12 | Low | Bulgarian, Polish, Portuguese and Turkish resources shipped, but were absent from both language selectors. | Add their existing language codes/autonyms to `arrays.xml` and `locales_config.xml`. | New resource test failed before the fix; checks every nonempty translated locale, selector agreement and label/value counts. |
| 13 | Low | `android:installLocation="auto"` was on `<application>`, where it did not set the package install policy. | Move it to `<manifest>`. | New namespace-aware XML test failed before the fix; final merged manifests checked. |
| 14 | Low | The smoke script expected ADPF to start enabled, although the recent default change disabled it. Its first toggle therefore failed its persistence assertion. | Expect enable first, then disable. | Compared against preference/preset defaults; Python syntax checked. Script not executed because adb/emulator use was prohibited. |
| 15 | Low | Release smoke testing unconditionally launched `LatencyOverlaySmokeActivity`, which exists only in debug builds. | Gate the rendering-only block on the script's existing `DEBUGGABLE` state. Release still checks overlay settings. | Debug/release source-set review and Python syntax check; no emulator run. |

The JNI lifetime and encoding conclusions follow Android's [JNI guidance](https://developer.android.com/ndk/guides/jni-tips): attached native threads retain local references until detachment, and JNI string functions use modified UTF-8.

The encoding impact is qualified using [ART's implementation](https://android.googlesource.com/platform/art/+/master/runtime/jni/jni_internal.cc): it explicitly preserves four-byte supplementary sequences for compatibility, but keeps modified encoding for zero and does not replace bad surrogates. Passing standard UTF-8 bytes avoids depending on that runtime-specific behavior.

## Audit inventory and decisions

The following inventory records the build/security boundaries and the functions examined in this area. Rendering, transport and controller algorithms were followed where they affect these boundaries; this is not a claim to have retested every hardware path.

### Build and packaging

- Root/app Gradle scripts, settings, properties, wrapper properties and launch scripts, both release scripts, lint configuration and ProGuard rules: plugin/repository resolution, signing presence/error paths, flavor IDs, SDK levels, Java/desugaring, dependencies, test forks, language/density splits, ABI filtering, native arguments and release shrinking. JDK 17, Gradle 9.7.1, AGP 9.4.0, compile SDK 37, target SDK 36, minimum SDK 21; root flavor maximum SDK 25. Language splitting is already disabled. Release debug-key fallback is explicit existing behavior and emits a warning; no artifact was published.
- Every `Android.mk`/`Application.mk`: module lists, root-only executable, static Opus/OpenSSL/CPU-features linkage, PyroWave 64-bit restrictions, C++ runtime, compiler/linker flags and prebuilt libraries. NDK 29.0.14206865, flexible-page support and both 16384-byte linker page-size flags are already configured. No speculative alignment or ABI changes were needed.
- All four manifests (main, root, nonRoot, debug), FileProvider paths, network-security, backup/data-extraction, game-mode and locale XML. Debug crash/overlay entry points are confined to debug. Application components without public intent filters remain private; launcher, frontend trampoline and poster access have deliberate external uses. FileProvider exposes only `cache/reports/` with read grants. Identity keys/certificates/preferences are excluded from both backup routes; crash records use no-backup storage. Arbitrary LAN discovery/pairing requires cleartext access, so globally disabling it would break supported hosts.

### Java boundaries

- `FrontendEntry`: constructor, `serialize`, `appendLine`, `parse`, `fileBaseName`, `esSystemBlock`, `esFindRuleBlock`, `mergeEsSystems`, `mergeEsFindRules`, `mergeBlock`, `xmlEscape`. Checked input limits, BOM/CRLF, sanitization, escaping, null optional fields and integer IDs. Findings 1–2.
- `ShortcutTrampoline`: service connection/disconnection and worker/UI callbacks, `validateInput`, `onCreate`, `readFrontendEntry`, `putIfPresent`, `findCachedApp`, `onStop`. Checked exported extras/content URIs, stream closure, UUID/name resolution, activity cancellation and service ownership. Finding 3; blocking content-provider I/O remains a device-test concern below.
- `PosterContentProvider`: static URI setup, `onCreate`, `openFile`, `openBoxArtFile`, `getType`, `query`, `insert`, `update`, `delete`, `createBoxArtUri`. Followed `DiskAssetLoader.getFile()` to the cache root. UUID/app-ID allowlists prevent path traversal, writes are rejected, and only box art is exposed. The redundant URI-match branch is harmless and was left alone.
- `HelpLauncher`: `launchUrl`, setup/troubleshooting/EOL launch helpers. `HelpActivity`: create/destroy/back handling, WebView page callbacks and back-dispatch registration. Internal fixed help links, no JavaScript interface, and explicit WebView teardown; JavaScript lint warning alone does not establish an exploit.
- `AndroidCryptoProvider`: constructor, `loadFileToBytes`, `loadCertKeyPair`, `generateCertKeyPair`, `saveCertKeyPair`, certificate/private-key/PEM getters and Base64 encoding. Followed RSA/SHA256/X.509 JCA lookups through the explicit BC provider and keep rules. Storage-failure recovery needs device validation; no crypto protocol was changed.
- `UsbDriverService`: state/touch/motion/battery forwarding, device-added/removed callbacks, receiver `onReceive`, binder listener/start/stop methods, `handleUsbDeviceState`, recognition/kernel/claim helpers, service create/destroy/bind/unbind. Checked main-handler ownership, permission cancellation, connection closing and API-specific PendingIntent/receiver rules. Finding 4.
- `EvdevCaptureProviderShim`: support check and reflective construction. Root `EvdevCaptureProvider`: constructor, handler thread, unrooted warning, synchronous network helper, show/hide cursor, enable/destroy; `EvdevReader.readAll/read`; `EvdevEvent` constants/constructor. Findings 8–9; legacy root lifecycle concerns require hardware validation.
- `ButterpolloApplication.attachBaseContext/onCreate`; `CrashCapture` constructor, handler installation, background startup/exit collection, report prompt/read and every activity lifecycle callback; `CrashRecord` constructor, create/Java-exception traversal, exit classification, sanitization, read/write/save/mark-shown; `RedactedLog` add/redact/snapshot, thread-name filtering, native tombstone decoding/varints; `ProblemReport` diagnostics/show/share. Checked locks/main-thread transitions, bounded reports, exception cycles, resource closure and grants. Best-effort crash-report failures intentionally do not replace the original crash.

## Device-only follow-up and residual risks

- Install/load both 64-bit APK variants on a real 16 KB-page Android device. ELF/APK inspection cannot prove vendor-loader/Vulkan behavior. Use Android's [16 KB page-size guidance](https://developer.android.com/guide/practices/page-sizes).
- Exercise a fresh minified install: generate/reload pairing keys, pair, reconnect, start/stop native callbacks and HDR, render PyroWave, and test root reflective capture where supported. Build success and mapping inspection do not prove JCA/JNI runtime behavior.
- Stress growing encoded frames and repeated HDR updates with CheckJNI/heap observations; test emoji and supplementary-script input through the actual host. JVM keyboard tests do not cross JNI.
- On API 21–32, grant/deny/cancel USB permission, detach during the prompt and attempt a foreign-app spoof. Repeat on current Android/OEM USB stacks.
- On a rooted API 21–25 device, race capture startup/destroy, toggle grab repeatedly and hotplug input devices. The legacy synchronous joins and socket-publication timing deserve ANR testing; loopback still lacks peer authentication. Partial native socket writes and ioctl failure handling also need stress evidence before a protocol/lifecycle rewrite.
- Open an entry from a deliberately slow content provider. Size is now bounded, but reading is still synchronous during activity creation; a stalled provider may cause an ANR.
- Test low-storage/interrupted certificate writes and recovery. The existing provider's best-effort storage paths can regenerate identity after I/O failure; this audit did not redesign identity persistence.
- TalkBack/switch access for custom virtual controls and card actions; Hebrew/RTL, large fonts, foldable resize/rotation and 120 Hz+/VRR devices. Static labels and policy tests cannot establish focus order, clipping or OEM display behavior. RTL support is not explicitly enabled in the manifest; changing it globally needs this review first.
- Remaining lint warnings were triaged, not baselined away. Examples: application-context discovery and disabled bundle language splitting already satisfy their warnings; newer manifest attributes intentionally no-op below their API; pinning, LAN cleartext and exported TV art have required uses. Layout/style/translation cleanup and API-annotation substitutions were left alone.

# Stream, decoder, pacing, codecs and audio bug hunt

Audit date: 2026-10-09. Starting revision: `10ba65e8` (main). Native core baseline: `874ac9548f1bd6f095ef2b435c42cdde460e7821`.

Read `PARITY-MATRIX.md`, `TROUBLESHOOTING.md`, decoder errata, and the latest 30 commits, including the recent pacing, ADPF, PyroWave and latency changes. Reviewed the application stream implementation and its native core paths described below. No host repository changes, commits, pushes, device commands or emulator runs.

## Confirmed bugs and fixes

19 findings fixed. Severity describes impact when the triggering condition occurs; it does not imply that every device encounters it. Related manifestations of one ownership bug are counted once.

| ID | Severity | Bug and root cause | Minimal fix | Verification |
| --- | --- | --- | --- | --- |
| S01 | High | `MediaCodecDecoderRenderer.findAv1Decoder()` could dereference a missing AVC decoder while comparing a non-whitelisted AV1 decoder's performance point. The unsupported-device check in `Game` runs later. | Require a non-null AVC decoder before that comparison. Preserve existing codec preference policy. | Branch/exception-path review; Android build. Instantiating vendor codec enumeration is outside the existing plain JVM fixtures. |
| S02 | Medium | The retry after an odd decoder crash count disabled reference-frame invalidation for AVC and HEVC but left AV1 enabled, repeating the feature suspected of causing the crash. | Disable all three RFI flags in that fallback. | Constructor and capability-mask review; Android build. Actual codec-crash recovery needs a device. |
| S03 | Medium | `FrameLatencyStats` evicted pending frames after 2,048 entries although callbacks have a five-second timeout and streams permit 1,000 FPS. Above roughly 409 FPS, a stall lost frames before they could be counted as presentation drops. PyroWave's matching native queue had the same bound. | Increase both bounded queues to 8,192. | New failing-first JVM test retains and expires 5,000 frames; retain coverage of bounded pending/CSV queues. Native build checks the matching PyroWave change. |
| S04 | Medium | PyroWave returned a completed decode timestamp even when image acquisition timed out, was not ready, or triggered swapchain recreation. Java treated every positive timestamp as a presentation submission, inflating released FPS and later reporting false presentation drops. | Record whether `vkQueuePresentKHR` accepted this frame and query it under the existing renderer lock. Keep the completed decode measurement. | Reviewed acquisition, recreation, success/suboptimal and error exits; JNI/NDK build. Vulkan timing behavior needs a device. |
| S05 | Low | `VideoStats.add()` treated an absent host-processing minimum (zero) as a real minimum, erasing an observed nonzero minimum. | Ignore absent incoming minima. | New failing-first `missingHostTimingDoesNotEraseObservedMinimum` JVM test. |
| S06 | Medium | `VideoStats.totalHostProcessingLatency` accumulated the session's 100-us values in a signed 32-bit integer, eventually wrapping negative. | Use `long` for the aggregate. | New failing-first `accumulatedHostTimingDoesNotOverflowAnInteger` JVM test sums to 3,000,000,000. |
| S07 | Medium | JNI video-buffer growth and HDR updates created local array references on long-lived attached native threads and never deleted them. Old frame buffers could stay rooted; repeated HDR updates could exhaust local references. | Explicitly delete the temporary local arrays after creating the global reference or delivering HDR metadata; handle failed allocation before use. | JNI ownership review and all-ABI build. Repeated HDR/resize stress requires Android. |
| S08 | Medium | The Opus callback decoded into a buffer sized for the negotiated maximum frame, then wrote the entire array even when Opus returned fewer samples. A shorter valid packet could replay stale PCM at the tail. | Pass `decodeLen * channelCount` through the JNI signature, `MoonBridge`, `AudioRenderer`, and `AndroidAudioRenderer.write()`. | Checked samples-per-channel versus interleaved-short units and every call site; Java/JNI build. No existing host-JVM JNI/AudioTrack fixture. |
| S09 | Medium | `RtpAudioQueue.handleMissingPackets()` compared elapsed microseconds with a deadline containing packet duration in milliseconds plus a separate microsecond term. Reordered audio was declared lost prematurely. | Convert the complete FEC-block duration to microseconds before adding the reorder allowance. | Native test covers 5/10/20-ms packets, exact deadline, deadline + 1 us and the unchanged no-reordering fast path. Test also fails against the original source. |
| S10 | High | Audio receive/decoder thread-creation failures closed `rtpSocket` while the already-running ping thread still used it. Connection unwind later closed it again, potentially closing a reused descriptor. | Leave socket ownership with `destroyAudioStream()`, which joins the ping thread and then closes it. | Traced both failures through `LiStartConnection()`/`LiStopConnection()` cleanup; all-ABI build. Thread-creation failure injection on Android remains untested. |
| S11 | Medium | `reassembleFrame()` only handled `LBQ_BOUND_EXCEEDED`. A concurrent queue shutdown returned `LBQ_INTERRUPTED`, leaking the decode-unit allocation and its buffers and reporting a frame as accepted. | Complete the rejected unit with `DR_CLEANUP` and return. | Native regression verifies both frees, no completion notification and cleared NAL ownership. It fails against the original source. |
| S12 | Medium | RTSP handshake errors after a parsed response skipped `freeMessage()`. Early ENet failures also bypassed common crypto cleanup. Repeated failed connections leaked memory/resources. | Free responses on non-200, missing payload, Opus parsing and session errors; route ENet failures through existing `Exit` cleanup. | Reviewed ownership at all handshake exits; native build. No new network/mock framework added. |
| S13 | Medium | `performRtspHandshake()` ignored `notifyAudioPortNegotiationComplete()` failures and continued after audio bind or ping-thread creation failed. | Propagate the error and free the current RTSP response. | Traced negotiation and connection-stage unwind; native build. |
| S14 | Medium | `RtspParser.insertOption()` replaced only `current->content` for duplicate headers, leaking the old allocated fields and the incoming option node. | Replace the list node in place and free the isolated old node according to its allocation flags. | Failing-first native duplicate CSeq/Session test checks last-value semantics and balanced allocations. |
| S15 | High | A truncated RTSP header without a terminating delimiter made `endCheck` point beyond the allocated message. End-of-message checks read adjacent memory and could accept it as a terminator. | Reject the out-of-range cursor before examining it. | Failing-first native test places a fake terminator beyond the allocation and verifies malformed status plus complete cleanup. |
| S16 | Low | The post-stream decoder-latency message labeled a negotiated PyroWave stream `UNKNOWN`. | Include the PyroWave format mask in the existing label branch. | Format-mask/branch review and Android build; no new UI fixture for a literal label. |
| S17 | Medium | `needsAsyncCallback()` indexes `IDX_DS_ADAPTIVE_TRIGGERS` (12), but the legacy packet tables contained only indices 0–11. Unrecognized packets on legacy ENet control streams could read outside the table. | Add the unused sentinel entry to the four legacy tables. | New compile-time native regression fails on all four original tables and passes after the fix; encrypted Gen 7 is checked too. |
| S18 | Medium | Header-only HDR and undersized termination control packets passed the general two-byte header check. Failed `BbGet8`/`BbGet16` calls left `enableByte`/`terminationReason` uninitialized. | Reject packets lacking the mandatory enable byte or short termination reason, releasing packet ownership. Optional older HDR metadata remains supported. | Packet-length/ByteBuffer contract review and all-ABI build. A full ENet receive/crypto fixture is not present. |
| S19 | Low | Periodic control pings sent eight bytes from a stack array after initializing only six, leaking two bytes and making the reserved tail nondeterministic. | Zero-initialize the existing eight-byte payload. | Payload layout and serialization review; all-ABI build. |

## Review inventory and reasoning

The entries below enumerate the functions reviewed within this area. Functions with the same lifecycle or data contract are grouped with their shared conclusion. Trivial getters/setters and interface declarations are explicitly identified. A review conclusion is not a claim that vendor hardware behavior was tested.

The complete Java files for video/audio bindings, stream configuration/connection, bitrate controllers and the JNI bridge were read. `Game` and `NvHTTP` are cross-cutting files: their complete streaming/display/lifecycle/negotiation sections were read; controller mapping, pairing, app-list UI and unrelated input implementation are outside this hunt. No Kotlin implementation occurs in these stream paths. Native application wrappers, renderer, framing, RTSP/SDP, video/audio/control streams, RTP queues, depacketizer, RTSP parser and blocking queue were read. Reviewed shared headers for wire structures and API contracts. Generated shader bytecode and third-party Opus, ENet, OpenSSL and Reed-Solomon implementations were not re-audited. The packaged PyroWave decoder exposes a header/prebuilt library, so its internal implementation cannot be audited here.

## Suspected issues and device-only verification

These are not included in the 19 confirmed fixes:

- **Display changes during a session:** fold/unfold, external-display moves and refresh-policy changes can invalidate the initially selected refresh maximum/ARR policy. Test Android 16 ARR, fixed 60/90/120/144/240-Hz modes and fractional rates through those transitions before adding a display listener or changing pacing policy.
- **Codec recovery and capability reporting:** exercise repeated flush/restart/reset, AV1 RFI fallback, hardware performance-point omissions, HEVC/AV1 Main10 HDR and explicit 4:4:4 on actual supported decoders. JVM profile-mask tests cannot prove vendor decode/display support.
- **Vulkan presentation:** exercise MAILBOX/FIFO/latest-ready where supported, missing/delayed display-timing callbacks, acquire timeout/not-ready, out-of-date/suboptimal swapchains, surface destruction and HDR toggles. A completed decode fence or presentation timestamp is not a photon-level measurement.
- **Audio routing:** stereo/5.1/7.1, changing Opus packet durations, Bluetooth/HDMI route changes, AudioTrack short writes/`ERROR_DEAD_OBJECT`, and teardown during a blocking write need device runs. No speculative restart or buffering policy was introduced.
- **JNI/resource pressure:** repeat HDR toggles, large frame-buffer growth, connection failures and forced worker-creation failures under memory pressure. Builds verify signatures, not ART reference-table behavior or descriptor reuse timing.
- **Native shared state:** HDR enabled/metadata, decoder refresh/drop state and RTT snapshots cross control/receive/decode/UI boundaries with lifecycle assumptions that merit stress/race instrumentation. No reproducible failure was established here; broad synchronization changes would be speculative. Existing producer/join ordering was traced before deciding not to alter it.
- **Vendor PyroWave decoder:** internal GPU decoder implementation is supplied prebuilt. Its memory safety, device-loss handling and shader correctness beyond the application wrapper require the corresponding source or vendor/device diagnostics.

No device, host session, physical HDR/VRR display, or end-to-end audio/video playback was used for this audit.

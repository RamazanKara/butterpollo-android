# Networking bug hunt

Audit: 2026-10-09. Android repository only, based on `10ba65e8` on this worktree's `main`. Changes remain uncommitted. No host repository changes, device commands, emulator runs, dependencies, or configuration options were added.

Read `PARITY-MATRIX.md`, `TROUBLESHOOTING.md`, the latest 30 commits, and the source inventory below. The scope is pairing/identity, HTTP and TLS, discovery/manual addressing, WOL, connection/reconnect control flow, JNI/socket/STUN/RTSP/SDP dependencies, caches, and host settings/storage. Media decoding, rendering internals, controller protocols, and third-party library internals are not a complete audit target. The networking/lifecycle portions of the mixed-purpose `Game` activity were traced separately.

## Findings and fixes

35 findings are fixed. High means authentication, saved-state loss, crash, or substantial availability impact; medium means connectivity, concurrency, or resource-management failure; low means a boundary error with limited impact. Related manifestations of the same root cause share one row.

`JVM` below names executable regression coverage. `Native` refers to the standalone C tests. `Review/build` means the failure path was established from code and the fix compiled/linted, but no Android framework/device runtime test was run. Those entries are not represented as unit-tested.

Framework-heavy fixes therefore have explicit review/device limitations above rather than fabricated Robolectric coverage.

## Device-only follow-up and remaining uncertainty

These are not included in the fixed count. A host/device setup is needed to determine their impact; no speculative transport/lifecycle rewrite was made.

1. **Overlapping NICs/subnets and VPN routing:** NSD now retains separate registrations, but IPv4 requests still generally use Android's default route. A Wi-Fi/Ethernet/VPN combination with overlapping private addresses needs testing. Temporary process binding for STUN can affect other newly opened sockets; the lock only serializes STUN operations. Verify that a lockdown VPN permits and restores the underlying route.
2. **IPv6 interface scope and network churn:** verify manual `%wlan0`/numeric scopes, IPv6-only discovery, link-local HTTP and pinned TLS, then stream setup after Wi-Fi reconnect or interface-index change. Java URL construction is covered; real Android routing and native address resolution are not.
3. **Discovery lifetime on OEM/API combinations:** repeatedly enter/leave PC view while NSD updates and host probes are delayed; repeat JmDNS multicast-lock acquisition/release on API 21-33. Lint's old-API Wi-Fi-context advisory needs a retention test. The callback lock fix is tested, but system callbacks, multicast filtering, and Wi-Fi power policy are not reproduced by JVM tests.
4. **WOL delivery:** existing code bounds mapped ports, tries all resolved addresses plus per-NIC broadcasts, and sends a burst. A successful UDP send is not an acknowledgement. Test sleeping hosts with stale ARP, Ethernet plus Wi-Fi, and VPN on/off; BIOS/NIC/subnet broadcast behavior remains hardware-dependent.
5. **Pairing/storage interruptions:** real host tests should cover PIN cancellation at every protocol step, EC/RSA host certificates, chain-bearing pins, disk-full/power-loss during identity save, and SQLite migration commit failure. Unit tests cover malformed data and key mismatch, but not Android storage durability. Identity regeneration after a damaged key pair still requires re-pairing.
6. **Reconnect/resume/lifecycle:** interrupt startup, disconnect during launch confirmation, reconnect repeatedly, background/rotate while callbacks arrive, and exercise input-only/remote-monitor roles. Existing owner/cancellation guards and confirmation tests were retained; actual socket/decoder callback timing remains device-dependent.
7. **Artwork and settings:** rapidly recycle image views during fade/retry, saturate the bounded executor queues to check discarded AsyncTask recovery, reopen many app grids and inspect worker retirement, and migrate a real legacy database. Test fractional/high-refresh profiles and VRR across fold/unfold and external-display changes; requested refresh settings can differ from the currently active physical mode. No decoder/display policy was changed.
8. **Android 16 network restrictions:** current Android 16 local-network protections are opt-in; permission-enforcement behavior must be exercised on an opted-in physical device before proposing a permissions change. See [Android local-network permission guidance](https://developer.android.com/privacy-and-security/local-network-permission) and [Android 16 behavior changes](https://developer.android.com/about/versions/16/behavior-changes-16).

The NSD network-key decision follows [`NsdServiceInfo.getNetwork()`](https://developer.android.com/reference/android/net/nsd/NsdServiceInfo). The scoped-IPv6 fix accounts for [OkHttp 5.5 route selection](https://raw.githubusercontent.com/square/okhttp/parent-5.5.0/okhttp/src/commonJvmAndroid/kotlin/okhttp3/internal/connection/RouteSelector.kt), which bypasses custom DNS for literal IP addresses.

Rows group functions that share an ownership model. `xN` includes overloads or separate nested callback implementations. Accessors and immutable value holders were checked against their writers/callers rather than given speculative defensive code. No networking Kotlin source was present in these directories.
